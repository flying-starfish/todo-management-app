# ローカル本番シミュレート

このガイドは、ローカルで本番相当の構成（PostgreSQL/Redis/Nginx）を確認するための最小手順です。

## ローカル本番シミュレートとは

「本番デプロイ前に、ローカル環境で本番に近い構成を再現して確認する」ための検証プロセスです。

開発用の軽量構成（例: SQLite + Vite 開発サーバー）とは目的が異なり、
運用時に問題になりやすい点を事前に洗い出すことを狙います。

## 目的

- 開発環境では見えにくい本番特有の問題を早めに発見する
- リリース前に構成・設定・接続の整合性を確認する
- デプロイ後の障害リスクを下げる

## 期待できる効果

### 1. 構成ミスの早期発見

- Nginx 経由のルーティング不備
- 環境変数の不足や誤設定
- DB 接続設定の不一致

### 2. 本番観点での動作確認

- API とフロントの接続性
- ヘルスチェックの応答
- 起動順序依存の問題

### 3. デプロイ手順の予行演習

本番に近い手順をローカルで一度回すことで、実運用時の作業ミスを減らせます。

## どのタイミングで実施するか

以下のタイミングで実施するのがおすすめです。

1. リリース前（必須）
2. インフラ・設定変更後（Nginx, DB, 環境変数）
3. 認証・通信まわりの仕様変更後

日常の機能開発ごとに毎回実施する必要はありません。
通常はローカル直起動や開発 Docker で高速に回し、節目で本シミュレートを実施します。

## 開発 Docker との違い

- 開発 Docker:
	- 目的: 開発効率と再現性
	- 特徴: 軽量・高速な反復向け

- ローカル本番シミュレート:
	- 目的: 本番移行前のリスク検知
	- 特徴: 本番相当の構成確認向け

## 事前チェック

- Docker / Docker Compose が利用可能
- 本番用の環境変数が定義されている
- ローカルの使用ポートが競合していない

## 起動

```bash
docker-compose -f docker-compose.prod.yml up -d --build
```

## 確認

- アプリ: http://localhost
- API ヘルスチェック: http://localhost/api/health

## 停止

```bash
docker-compose -f docker-compose.prod.yml down
```

## 完全リセット

```bash
docker-compose -f docker-compose.prod.yml down -v
```
